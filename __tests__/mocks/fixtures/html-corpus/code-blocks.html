Writing a Tiny Expression Parser in TypeScript

Marco Bellini, February 2, 2024

Recursive-descent parsers are one of those techniques that look intimidating until you write one. In this post we will build a parser for arithmetic expressions like 1 + 2 * (3 - 4) in under a hundred lines, and handle operator precedence without a single table.

Tokens first

The tokenizer turns a string into a flat list of tokens. Note the comparison operators: they are why HTML escaping matters when you publish code on the web.

type Token =
  | { kind: 'num'; value: number }
  | { kind: 'op'; value: '+' | '-' | '*' | '/' | '<' | '>' }
  | { kind: 'paren'; value: '(' | ')' };

function tokenize(src: string): Token[] {
  const out: Token[] = [];
  let i = 0;
  while (i < src.length) {
    const ch = src[i];
    if (/\s/.test(ch)) { i++; continue; }
    if (/\d/.test(ch)) {
      let j = i;
      while (j < src.length && /[\d.]/.test(src[j])) j++;
      out.push({ kind: 'num', value: Number(src.slice(i, j)) });
      i = j;
      continue;
    }
    if ('+-*/<>'.includes(ch)) { out.push({ kind: 'op', value: ch as never }); i++; continue; }
    if (ch === '(' || ch === ')') { out.push({ kind: 'paren', value: ch }); i++; continue; }
    throw new SyntaxError(`Unexpected "${ch}" at ${i}`);
  }
  return out;
}

Precedence by recursion

Each precedence level gets its own function. Lower-precedence functions call higher-precedence ones, so multiplication binds tighter than addition for free.

function parseExpr(): number {
  let left = parseTerm();
  while (peek()?.value === '+' || peek()?.value === '-') {
    const op = next().value;
    const right = parseTerm();
    left = op === '+' ? left + right : left - right;
  }
  return left;
}

function parseTerm(): number {
  let left = parseFactor();
  while (peek()?.value === '*' || peek()?.value === '/') {
    const op = next().value;
    const right = parseFactor();
    left = op === '*' ? left * right : left / right;
  }
  return left;
}

A quick shell session to check it works, including the && chaining and a redirect:

$ npx tsx parser.ts "1 + 2 * 3" && echo ok
7
ok
$ npx tsx parser.ts "(1 + 2" 2> err.log; cat err.log
SyntaxError: expected ")" at end of input

Inline code also needs escaping: if (a < b && b > c) must survive the round trip. And here is an HTML snippet shown as code:

Wrapping up

That is the whole trick: one function per precedence level, a cursor over the token list, and a clear error when something unexpected shows up. From here you can add unary minus, exponentiation with right associativity, or variables, each in a handful of lines.
